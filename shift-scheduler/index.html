11B 排班規劃

前端原型 V1｜尚未連接 Google Apps Script / OpenAI API

● 前端測試模式

先把「本月需求」說清楚，再讓規則引擎排班

這一版先確認護理長實際操作是否順手。固定規則、人員、本月需求、AI解析後確認、班表與規則檢核都先放到同一個介面；目前所有資料只存在這台裝置的瀏覽器，不會送到 AI，也不會產生 Token 費用。

預計正式流程

1
輸入本月特殊需求用自然語言一次說完
2
AI 解析為排班規則只負責理解，不直接排班
3
護理長確認AI 聽錯可直接修正
4
排班引擎計算硬規則必須遵守
01 固定規則一次設定、長期沿用
02 本月需求護理長自然語言輸入
03 確認解析AI 規則逐條確認
04 產生班表演算法計算
05 人工調整即時檢核違規

基本設定

先選排班月份與使用情境；正式版會由 Google Sheet 帶入。

① 固定排班規則

先放入目前討論過的規則草案。正式接排班引擎前，會再逐條與你確認。

目前這些是「前端規則草案」，尚未真正執行排班計算。硬規則之後會由程式鎖死；最佳化規則只會盡量滿足。

② 本月排班人員

V1 先讓你確認需要哪些欄位；之後可改成從 Google Sheet 自動帶入。

姓名／代號職類資歷/角色主要班別可帶新人

③ 請直接描述本月特殊需求

這裡就是未來真正會呼叫 API 的入口。

V1 尚未接 OpenAI API。
按「AI 解析本月需求」只會提示尚未連線，不會把文字送出去。等我們下一階段完成 Google Apps Script 後，這顆按鈕才會真正把內容送到後端。
正式版預計：
AI 只把自然語言轉成固定格式的排班條件，護理長確認後，才交給排班引擎。AI 不直接決定最終班表。

④ AI 解析結果確認

正式版每一條都可以人工修正；確認後才會成為本月規則。

人員日期／期間系統理解性質確認
尚無解析結果。可先按「載入示範解析結果」查看操作方式。

⑤ 班表預覽

目前只顯示版型；之後由排班演算法產生，不會靠 AI 自由生成。

⑥ 規則檢核

正式版在產生班表與人工調班時即時更新。

○ 最低人力配置｜待接排班引擎
○ 連續工作天數｜待接排班引擎
○ 班別轉換／休息規則｜待接排班引擎
○ 資深／帶教搭配｜待接排班引擎
○ 本月硬性需求｜待接排班引擎
○ 偏好達成情形｜待接排班引擎
