# 115年度護理部 EPAs 系列課程｜學分補查

這個模組接到現有 Learning Hub 首頁，使用獨立 Google Apps Script + 私人 Google 試算表，不改動既有課程預約與教學工具資料。

## 檔案

- `credit-check.html`：GitHub Pages 公開入口，不接收身分證字號。
- `Code.gs`：獨立 Google Apps Script 後端，包含護理長信箱驗證、資料查核、12/05 截止及去重。
- `Index.html`：在 Google Apps Script 內提供實際填寫頁面。

## 快速啟用（承辦人操作）

1. **先完成院內核准**：確認本次以 Google Apps Script / Google 試算表處理教師個資，包含蒐集告知、存取權限、保存期間及刪除程序。正式上線前，請由院內資訊與個資權責人員確認驗證設計是否適用。
2. 用承辦人的受控帳號建立**全新私人 Google 試算表**，名稱例如「115年度 EPAs 系列課程學分補查」；不要使用原課程預約試算表。不要設為「知道連結的任何人」。
3. 在試算表點「擴充功能 → Apps Script」。將 `Code.gs` 貼入程式碼檔，再新增 HTML 檔案，名稱**正好是 `Index`**，貼入 `Index.html` 內容。
4. 在 Apps Script 編輯器的函式選單選擇 `initialize` 執行一次並完成授權；會建立：`補查資料`、`護理長權限`、`異動紀錄`。重複執行不會清除資料。
5. 在 `護理長權限` 工作表加入各單位護理長；每人一列：`單位`、`護理長姓名`、`院內信箱`、`啟用（是／否）`。例如信箱須為 `@tzuchi.com.tw`，狀態填 `是`。實際名單請透過院內核准來源建立，勿公開上傳。
6. 部署前先在 Apps Script 手動執行 `getFormStatus`（僅確認程式可執行），再部署新的 Web App：**執行身分：我**；存取權依院內政策設定。若沒有全院 Google 網域，使用「任何人」時仍須依賴院內信箱 OTP，**不得視為等同院內帳號登入**。須經院內權責單位確認後才正式收件。
7. 以已列入權限名單的護理長院內信箱測試：收到六碼 OTP → 驗證成功 → 回填一位**虛構測試教師** → 試算表僅出現身分比對碼及遮蔽顯示，沒有完整身分證字號。測試完移除測試資料。
8. 從部署結果複製 `https://script.google.com/macros/s/.../exec` URL。打開 GitHub 專案 `credit-check.html`，把 `SECURE_CREDIT_FORM_URL = ''` 中的空字串改為**新部署的安全表單 URL**。絕不要放原預約 API URL。
9. 重新檢查新頁在手機上可開啟、不能跨單位編修、截止後拒絕提交，再將新入口通知各護理長。

## 一筆回填包含

`單位`、`護理長姓名`、`院內信箱`（登入後自動帶入）、`教師全名`、`教師完整身分證字號`（僅在傳輸中供伺服器建立 HMAC 比對值）、第一堂狀態、第二堂狀態、第三堂狀態、已完成實作者之 `PGY 學員全名`。

第三堂紙本仍需要教師及 PGY 學員親筆簽名、護理長核章，交回承辦人後才可認列學分。此表只記錄補查需求，不會自動入學分。

## 資料安全邊界

- GitHub 頁面只放一般內容與通往 Apps Script 的連結；**不放表單輸入欄位、身份證資料、院內名單、帳號密碼或私密金鑰**。
- Apps Script 以 `@tzuchi.com.tw` 院內信箱之 OTP 驗證填寫者，並與私人 Sheet 的 `護理長權限` 白名單核對。OTP 在 10 分鐘內有效，驗證後工作階段 30 分鐘。
- 身分證字號在伺服端產生以秘密金鑰保護的 HMAC-SHA256 比對值；Sheet 只記錄 HMAC 與遮蔽版本，**不保留可還原的原文**。秘密金鑰僅存 Apps Script Script Properties。
- 試算表只能由授權管理人員讀取；不得以一般公開或連結共用方式分享。不要把身分證、OTP 或工作階段 token 寫入郵件、URL、GitHub、瀏覽器儲存空間或除錯紀錄。
- OTP 是以院內電子信箱作為驗證渠道；若院內政策要求機構身分驗證、多因素驗證或不得使用外部雲端，**請改走院內核准的系統**，不要僅靠這個網頁收集身分證字號。
- 完成學分補查後，依院內核定的保存期限清除資料、Google Drive 版本紀錄及適用的備份；不要自行假設永久保留。

## 已知限制

1. 目前無法從 GitHub 直接替你部署 Google Apps Script；這一步必須由具備 Google 帳號授權的操作者執行。
2. 此設計若使用「任何人」可存取的 Web App，雖然提交需要院內信箱 OTP，但仍不是院內單一登入。正式啟用前應完成院內資安審核。
3. 如學分系統必須拿到完整身分證號碼進行匯入，這個版本**不提供原文匯出**，需要改用經院內核准的安全流程。
